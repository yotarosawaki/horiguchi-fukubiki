# 堀口製茶 × ICONSIAM 高島屋　福引クーポン

お茶の売場で購入者が福引を引き、別フロアの喫茶コーナーで使えるクーポンを発行して送客するWebアプリです。

## 全体の流れ

1. 売場スタッフが **staff.html** でレシート番号を入れて「抽選する」を押す
2. 大型モニターの **monitor.html** で福引（ガラガラ）の演出 → 当選結果とクーポンQRを表示
3. お客様はQRをスマホで読み取る（**coupon.html** が開く）か、画面を写真に撮る
4. 喫茶コーナーの **cafe.html** でQRを読み取る（または6文字コードを入力）→「使用済みにする」
5. **admin.html** で景品・当選確率・在庫・期限・PINの設定と、送客率の集計を確認

| 画面 | 置く端末 | PIN |
|---|---|---|
| monitor.html | 売場の大型モニター（PC / スティックPC など） | 売場スタッフ用 |
| staff.html | 売場のタブレット・スマホ | 売場スタッフ用 |
| coupon.html | お客様のスマホ（QRから開く） | 不要 |
| cafe.html | 喫茶コーナーのタブレット（カメラ付き） | 喫茶店用 |
| admin.html | 担当者のPC | 管理者用 |

PIN は端末ごとに一度入れれば、その端末に記憶されます（「端末設定を解除」で消せます）。

## 不正防止の仕組み

- **抽選はスタッフしか始められない**：抽選の発行には売場スタッフ用PINが必要です。
- **同じレシートで2回は引けない**：レシート番号はサーバー側で重複を確認します。
- **当たりは画面ではなくサーバーで決まる**：当選確率と在庫上限はサーバーで処理するため、画面を細工しても当たりは変えられません。
- **クーポンは1回だけ使える**：喫茶店で「使用済み」にした時点でサーバーに記録されます。写真やスクショを共有しても2回目は「使用済み」と表示されます（2台で同時に押しても成功するのは1回だけです）。
- **偽造できない**：QRの中身は推測できない32桁のランダムIDです。6文字コードの照会には喫茶店用PINが必要です。
- **有効期限**：発行当日のみ／◯日後まで／イベント最終日まで、を管理画面で設定できます（タイ時間）。
- **PINの総当たり対策**：5分間に50回間違えると、そのPINは一時的に使えなくなります。PINは8桁程度をおすすめします。
- **記録が残る**：発行日時・レシート番号・景品・利用日時を管理画面で確認でき、CSVで書き出せます。不審なクーポンは無効にできます。

> スタッフが架空のレシート番号で抽選を発行することは仕組みだけでは防げません。管理画面の一覧（CSV）とPOSのレシート記録を突き合わせて確認してください。

## まず試す（試用モード）

サーバーなしで、このPCのブラウザだけで一連の流れを試せます。現在の config.js は本番（`backend: 'supabase'`）なので、URL の末尾に `?backend=mock` を付けて開いてください（例: http://localhost:8765/?backend=mock）。本番のデータには触れません。

```bash
python -m http.server 8765
```

ブラウザで http://localhost:8765/ を開き、モニター・売場スタッフ・喫茶店・管理を別々のタブで開いてください。
試用モードのPINは、売場 `111111`、喫茶店 `222222`、管理 `999999` です。

試用モードのデータはそのブラウザの中だけに保存されます。スマホでQRを読み取っても、別の端末なのでクーポンは表示されません。端末をまたいだ確認は、次の本番設定のあとに行ってください。

## 本番の設定（Supabase）

1. https://supabase.com で無料アカウントとプロジェクトを作成（Region は **Southeast Asia (Singapore)** がおすすめ）
2. 左メニュー **SQL Editor** を開き、`supabase/schema.sql` の中身を全部貼り付けて **Run**
3. 同じ SQL Editor で、PIN を設定（数字は自分で決めたものに置き換える）
   ```sql
   select public.set_pin('staff', '12345678');
   select public.set_pin('cafe',  '23456789');
   select public.set_pin('admin', '34567890');
   ```
4. **Project Settings → API** の「Project URL」と「anon public」キー（または publishable キー）を `assets/js/config.js` に貼り、`backend` を `'supabase'` にする
   ```js
   backend: 'supabase',
   supabaseUrl: 'https://xxxxxxxx.supabase.co',
   supabaseAnonKey: 'eyJ...（または sb_publishable_...）',
   ```
5. GitHub Pages などHTTPSのサイトで公開する（喫茶店のカメラは HTTPS でないと動きません）

anon キーは画面のプログラムに入りますが、公開されて問題ない種類のキーです。テーブルは直接読み書きできないようにしてあり、操作はすべてPIN確認付きの関数を通ります。**service_role キーは絶対に config.js に入れないでください。**

## 景品の設定

管理画面の「景品設定」で変更できます。

- **当選比率**：数字の比で当たりやすさが決まります（例: 5 / 15 / 30 / 50 なら 5% / 15% / 30% / 50%）
- **発行上限**：その景品を出す最大数。上限に達すると、残りの景品だけで抽選します。空欄なら無制限です
- **使う**：外すと抽選に出なくなります
- 必ず1つは「無制限」の景品を残してください（全部が上限に達すると抽選できなくなります）

初期値の景品（抹茶ラテ無料など）は仮のものです。堀口製茶さまと内容を決めて差し替えてください。

## タイ語への切り替え（納品時）

画面の文字はすべて `assets/lang/ja.js`（日本語）と `assets/lang/th.js`（タイ語）にあります。

- 切り替え：`assets/js/config.js` の `lang: 'ja'` を `lang: 'th'` にする（URL に `?lang=th` を付けても一時的に切り替わります）
- `th.js` は下訳です。**納品前にタイ語ネイティブの確認を受けてください**
- 「○階 喫茶コーナー」(`cafe_place`) やイベント名 (`event_name`) は、会場が決まったら両方のファイルで書き換えてください
- 景品名のタイ語は、管理画面の「景品名（タイ語）」に入力します
- 日付はタイ語表示のとき仏暦（例: 2569）で表示されます

文言を変えたら、各HTMLの `?v=2` の数字を1つ上げると、端末に古いファイルが残りません。

## 当日の運用メモ

- モニターは開いたら一度クリック（全画面表示と効果音が有効になります）
- お客様がQRを撮り逃したら、staff.html の「モニターに再表示」で同じクーポンをもう一度出せます（抽選はやり直されません）
- モニターが故障したら、staff.html の「QRを表示」でタブレットから読み取ってもらえます
- ネット接続が切れると抽選・消し込みはできません。売場・喫茶店とも、モールWi-Fiに加えてモバイル回線の予備を用意してください
